# 集装箱物流信息管理系统 · 前端

客户、订单、货物、集装箱、船舶、港口等业务数据的管理后台,以及配套的字典维护、操作日志与 Excel 导出。

---

## 技术栈

| | |
|---|---|
| 框架 | Vue 3(`<script setup>` 组合式 API) |
| 构建 | Vite |
| UI | Element Plus(含 `@element-plus/icons-vue`) |
| 路由 | Vue Router(History 模式) |
| 状态 | Pinia |
| 请求 | axios |
| 语言 | JavaScript(**没有用 TypeScript**) |

> 依赖版本以 `package.json` 为准。本项目在 **Node 24 / npm 11** 上开发。

---

## 快速开始

```bash
npm install
npm run dev
```

打开 `http://localhost:5173`,用系统里的账号登录。

**必须先启动后端**,否则页面能打开但数据全是空的(而且会弹"无法连接服务器"):

- 后端地址:`http://localhost:8080`
- 启动: IDE 运行 `HangyunApplication`,或 `mvn spring-boot:run`
- 接口文档:`http://localhost:8080/swagger-ui/index.html`

### 可用脚本

| 命令 | 作用 |
|---|---|
| `npm run dev` | 启动开发服务器(`http://localhost:5173`) |
| `npm run build` | 打包到 `dist/` |
| `npm run preview` | 本地预览打包产物 |

- 客户列表 →「订单查询」→ 看该客户名下的订单
- 订单列表 → 点客户姓名 → 弹框选「查询更多订单」或「查看客户详细信息」
- 订单列表 →「货物增加」→ 就地给这张订单登记货物

- 集装箱列表 →「查看箱主 / 查看操作方」→ 跳到公司管理
- 公司列表 →「集装箱详情」→ 看这家公司作为箱主 / 操作方的集装箱

## 配置

### 后端地址

**默认不用配** —— `src/api/request.js` 会按"当前页面是从哪个主机打开的"自动推:

| 从哪打开页面 | 请求的后端 |
|---|---|
| `http://localhost:5173` | `http://localhost:8080` |
| `http://192.168.x.x:5173` | `http://192.168.x.x:8080` |

所以同一个开发服务器**在本地和局域网里都能用**,不用改配置。

> ⚠️ 这个设计是有原因的:如果写死 `localhost:8080`,局域网里另一台设备打开页面后,
> 浏览器会去请求**它自己的** localhost —— 那儿没有后端,于是**页面能打开但数据全是空的**,
> 这种"看起来正常其实全挂"的故障最难排查。

想固定成别的地址(比如后端在另一台机器),在 `.env.development` 里设 `VITE_API_BASE_URL` 覆盖。

### 局域网访问

开发服务器默认监听所有网卡(`vite.config.js` 里 `server.host: true`),所以局域网里其它设备
直接访问 `http://<你的IP>:5173` 即可。

> 连不上八成是**防火墙**:Windows 默认会拦外部进来的连接。
> 另外后端 8080 也要放行,否则页面能打开但没数据。

## 登录与鉴权

**除登录接口外,所有接口都要带 `Authorization: Bearer <token>`**,否则返回 401。

这套逻辑全部在 `src/api/request.js` 里统一处理,业务代码不用管:

- **请求拦截器** —— 自动加上令牌
- **响应拦截器** —— 收到 401 就清掉本地令牌并跳登录页

有几个地方容易踩,改动前请先看 `request.js` 里的注释:

1. **登录接口自己的 401 是「用户名或密码错误」**,不能和"登录失效"混为一谈 ——
   否则用户在登录页输错密码会被弹"登录已失效"然后原地跳转。
2. **导出接口的响应是文件流,不是 JSON** —— 成功分支不能一刀切地扒 `.data.data`;
   失败时返回的 JSON 错误也会被当成 Blob 收下来,得读回文本才能拿到 `msg`。

令牌存在 `localStorage`(见 `src/utils/token.js`)。它**没有放在 Pinia 里**,因为路由守卫和
响应拦截器都要用它,而它们 import store 会绕成 `store → api → request → router` 的环。

## 开发约定

### 提交表单

- **新增接口大多不返回数据**,成功后要**重新拉列表**,不要把本地拼的数据当权威
- 有几个接口是**整体覆盖**语义(PUT 时没传的字段会被置 null),编辑表单必须**完整回填再提交**
- 时间字段一律用 `value-format="YYYY-MM-DD HH:mm:ss"` —— 别让 `Date` 对象进 JSON,
  序列化出来的带 `Z` 和毫秒的 UTC 串后端会拒绝

### 界面文案

**不要把实现细节写给用户看。** 判断标准是"这个词是在说系统怎么实现,还是在说用户会遇到什么":

| ❌ 不要写给用户 | ✅ 写给用户 |
|---|---|
| 这是物理删除,删除后无法恢复 | 删除后无法恢复 |
| 名称是前缀匹配,只能从开头匹配 | 名称只能从**开头**匹配 |

**代码注释和设计文档不受此限** —— 那里就该用准确的技术词。

### 表格列

**默认不显示自增 id**(内部标识,用户拿着没用)。两个例外:订单号(业务标识,用户要拿去对账)、
状态字典的 id(后端写死的语义,提示条里直接引用了)。

### 下拉框

"远程搜索下拉"的统一逻辑在 `composables/useRemoteSelect.js`,它解决三件事:
防抖、丢弃过期响应、**回填时把选中项补回选项列表**(否则 `el-select` 会退化成显示 id 数字)。

> ⚠️ 目前还有**四个较早的表单**是自己写的这套逻辑,没有迁移过来
> (`OrderFormDialog` / `PackingFormDialog` / `ContainerFormDialog` / `ContainerTrailerRecordFormDialog`)。
> 新写的地方请用 `useRemoteSelect`。

## 常见问题

**页面能打开,但所有列表都是空的**

后端没启动。所有接口都会弹"无法连接服务器,请确认后端已启动"。

**登录之后一直跳回登录页**

可能是令牌失效(会被 401 拦截器踢回去)。打开浏览器控制台看有没有 401;
也可以清掉 localStorage 里的 `hangyun_token` 重新登录。

**点某个按钮没反应**

先按 `Ctrl+Shift+R` 硬刷新。开发时改过代码后,页面有时会停在一个"不完整的热更新"状态 ——
模板更新了(按钮能看到)但脚本没重新加载,点下去 Vue 只在控制台报错、界面上什么都不发生。

**导出的文件打不开 / 显示乱码**

检查请求有没有带 `responseType: 'blob'`。带了这个才是文件流,否则拿到的是被当成文本的二进制。

**导出提示"导出行数超过 50000 条"**

后端限制。缩小筛选条件(比如加个时间区间)再导。
